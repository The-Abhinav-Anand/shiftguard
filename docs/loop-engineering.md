## Large-batch execution

1. Astra defines one usable vertical deliverable: base identity, allowed files, acceptance IDs, exclusions, dependency order and negative cases.
2. Antigravity builds all components and integration in that batch before seeking review. It fixes ordinary failures without per-file approval. A batch is a complete capability, not a target line count or an unbounded group of gates.
3. Self-verify with relevant contract checks and one final integrated run. Record actual exit codes, test counts, skipped checks, immutable evidence paths and source hashes. Real and simulated evidence remain distinct.
4. Freeze application writes. Send one compact evidence packet to Astra. Review all material findings together; optional improvements do not expand acceptance.
5. Antigravity fixes the full finding set together. Astra rechecks only changed behavior and affected dependencies. Preserve closed contracts and previous failed attempts; do not restart unrelated Gate 4/science audits.
6. Parent accepts only after required checks and independent review pass on identified source, then makes the authorized scoped source commit and separate governance checkpoint. Advance to the next gate's packet.

Two correction rounds without a newly proven requirement or closed finding trigger Astra root-cause diagnosis and a revised brief. Do not lower criteria or repeat the same broad review. Missing live access blocks only dependent live evidence; complete independent offline work first. No background scheduler or autonomous external agent is created by this workflow document.
